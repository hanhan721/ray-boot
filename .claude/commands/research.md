# Research - 研究调研命令

你现在处于研究调研模式。在这个模式下，你的核心原则是：**先理解，再行动；只调研，不写码。**

## 核心原则

- **广泛阅读后再下结论** - 不要看了一个文件就急着总结
- **多问澄清问题** - 遇到不确定的立刻询问
- **边研究边记录** - 发现什么记录什么，不要到最后才整理
- **不写代码** - 在理解完全清晰之前不动任何代码

## 调研流程

### 1. 理解问题
- 明确调研目标是什么
- 问题的边界和范围在哪里
- 需要回答哪些关键问题

### 2. 探索相关代码/文档
- 扫描项目结构和文件组织
- 阅读相关模块的代码实现
- 查阅项目文档和注释
- 分析数据模型和数据流

### 3. 外部调研（如需要）
- 搜索相关技术文档和最佳实践
- 对比类似项目的实现方式
- 查阅框架/库的官方文档
- 了解行业标准和规范

### 4. 形成假设
- 基于已收集的信息形成初步判断
- 明确假设的前提条件
- 识别需要进一步验证的点

### 5. 验证假设
- 用代码中的证据验证判断
- 交叉对比多个信息源
- 标注确定性等级（确定/较确定/不确定）

### 6. 输出调研报告

```markdown
# 调研报告：[主题]

## 调研目标
[要回答什么问题]

## 关键发现
1. **发现1**：[描述] - 确定性：高/中/低
2. **发现2**：[描述] - 确定性：高/中/低

## 现状分析
[当前系统/代码是怎么做的]

## 可选方案
| 方案 | 描述 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| A | ... | ... | ... | ... |
| B | ... | ... | ... | ... |

## 建议
[推荐哪个方向，为什么]

## 待解决的问题
- [ ] 问题1：[需要进一步确认什么]
- [ ] 问题2：[需要谁来决策]

## 参考资料
- [相关链接或文档]
```

## 调研优先使用的工具

- **Read** - 理解代码实现
- **Grep / Glob** - 查找模式和文件
- **WebSearch / WebFetch** - 查阅外部技术文档
- **Task + Explore** - 探索代码库结构
