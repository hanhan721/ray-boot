# 会话管理与在线分页

项目没有迁移机制，`docs/sql/` 是全量初始化脚本：新环境直接执行即可获得完整表结构（含 Refresh Token 的稳定登录标识 `login_session_id`）；已有开发库须显式重建，重建会清空既有凭据与在线会话数据。

Access Token 每次刷新继续轮换，`loginSessionId` 在一次登录期间保持不变。旧 Refresh Token 标记为已轮换，不能用于续期；在它原本的有效期内，仍可用于登出定位。登出在用户行锁内撤销该次登录的当前凭据及轮换历史，不影响其他设备。沿用现有 Refresh Token 过期清理任务清理历史记录。

在线列表改为 `GET /api/sys/online/page`，返回 `R<IPage<OnlineUserVO>>`。参数为 `pageNum`（默认 1）、`pageSize`（默认 10，最大 500），以及可选的 `startTime`、`endTime`（ISO 本地日期时间，包含边界，毫秒精度）。例如：

```text
/api/sys/online/page?pageNum=1&pageSize=20&startTime=2026-11-03T00:00:00&endTime=2026-11-03T23:59:59.999
```

旧 `/list` 接口移除。用户名、IP 模糊查询移除。会话按登录时间倒序，同一毫秒按会话摘要倒序排列；与原实现一致，刷新签发的新会话使用刷新时间。列表是实时分页，翻页期间的新增、过期和撤销可能改变页边界和总数，不提供跨请求快照。

列表只通过 Valkey ZSET 获取当页摘要，再批量读取展示字段，不读取角色和权限快照。两个索引分别保存登录时间和实际过期时间；撤销、事务回滚同步删除索引。后台及每次分页最多清理 1000 条过期记录；积压超过单次额度时，分页明确返回“在线会话索引正在清理，请稍后重试”，后台继续清理，避免一次请求无界处理积压。

首次升级后，在调度管理中手动执行一次 Bean `onlineSessionIndexTask` 的 `rebuild` 方法，为既有会话补齐索引。该任务按 200 条分批扫描，只读登录时间，并以会话 Hash 的实际剩余 TTL 建立过期索引；可重复执行，不延长会话寿命。请求处理不执行回填扫描。新签发的会话自动写入索引。
